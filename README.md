# Afthal Ahmadh — WordPress Developer Portfolio

Static single-page portfolio built with Next.js (App Router), TypeScript and
Tailwind CSS v4. This site shows only WordPress, WooCommerce and CRM work —
mobile apps and automation live on the other portfolios. Flat bento layout,
blue/white accent, Bricolage Grotesque. Brands use their official logos in
full colour: simple-icons (CC0) and the Iconify "logos" set (CC0) for
monday.com. Lucide icons cover things that aren't brands, such as CRM, REST
APIs, multilingual sites and site care.

The page is five blocks, in this order:

1. **Overview** — photo, role, tagline, location, years of experience and the
   three categories.
2. **Projects** — directly under the overview, with category tabs (All,
   WordPress Sites, WooCommerce Stores, CRM).
3. **Experience** — software roles and education.
4. **Technologies** — four groups: WordPress, web, site care, CRM &
   integration.
5. **Contact** — email, LinkedIn, GitHub, Credly and CV links.

The footer links to my other portfolios once their URLs are set in
`otherPortfolios`.

## Run it

```bash
npm install
npm run dev
```

Then open http://localhost:3000.

## Build the static site

```bash
npm run build
```

This writes a plain HTML/CSS/JS site to `out/` (`output: "export"` in
`next.config.ts`). Upload that folder to any static host — Netlify, Vercel,
GitHub Pages, Cloudflare Pages or a plain web server.

Stop the dev server first — `next build` and `next dev` share `.next`.

## Edit your real details

Everything personal lives in one file: [`src/config/site.ts`](src/config/site.ts).

Any field left as an empty string is treated as *not provided yet*: the site
hides the link or shows a neutral note instead of publishing a broken URL or an
invented value.

| Field | Where it shows |
| --- | --- |
| `profile.*` | Overview tile (name, role badge, tagline, location, photo) |
| `contact.*` | Contact card, header and footer links |
| `experience[].start` | The earliest start drives the years-of-experience figure |
| `categories` | Tab names and order; the "What I build" tile |
| `technologies` | Technologies section groups and items |
| `projects[]` | Project cards |
| `otherPortfolios` | "More of my work" links in the footer (empty = hidden) |

### Adding a project

Add an entry to `projects` with a `category` of `wordpress`, `woocommerce` or
`crm`. Websites use a landscape `image` — a 1440×720 capture of the live site
in `public/projects/sites/` — and a "Visit site" link. CRM platforms without a
screenshot use `brand` or `letters`. List in `tools` what the site actually
loads (theme, page builder, key plugins), and only fill `outcome` with a
result you can back up. A category with no projects shows "… projects are
being added" under its tab.

### CV file

`public/afthal-ahmadh-cv.pdf` is generated by
[`scripts/build_cv.mjs`](scripts/build_cv.mjs): it lays the CV out as HTML in
Poppins (bundled in `scripts/cv/fonts`, SIL Open Font License) and prints it to
A4 with headless Chrome, so every link stays clickable.

```bash
npm run cv
```

The script holds its own copy of the facts (it also lists the Production
Manager role, which the site leaves out, and the mobile apps after the web,
WordPress and CRM work), so re-run it after editing it to keep
the CV and the site in step. Set `CHROME` to the browser binary if Chrome is not
in `/Applications`.

## Structure

```
src/
  app/              layout (SEO metadata, font), page, global styles + theme colours
  components/
    sections/       header, intro (overview), projects, experience, technologies, footer
    contact-tile    contact card
    category-icon   icon per project category
    ui/             button, card, badge, section, brand icons
  config/site.ts    all editable content and links
  lib/              year figures, date helper, cn()
```

The theme colours are the `--color-*` tokens at the top of
`src/app/globals.css` (blue accent: `#2563eb`, `#1d4ed8`, `#eff6ff`). The CV uses its own blue (`BLUE` in
`scripts/build_cv.mjs`).
